# NICE history conventions

Current and monthly measures use the same `nice_indNNN` macro. Monthly results have one row per eligible person, indicator and completed month-end for the preceding 60 months. They use today's retained records and code lists, so later corrections can change earlier results. Measure models, current and monthly, are tables, so data tests and family unions read stored results; family snapshot inputs are views.

Join, group and select evidence by person and reporting date. Use the historical active population and registration practice at that date. Preserve each measure's age, date boundaries, evidence selection and known-date rules. Ordinary clinical evidence is capped at the reporting date; recorded-date caps apply where the established definition requires them.

Only people whose follow-up window has closed by the reporting date are included, whether or not they achieved. For a single index event, move the cohort back by the follow-up length and retain its NICE duration. Apply NICE annual financial-year cohorts as rolling 12 months ending one follow-up window before the reporting date. Set `measurement_period_start` to the shifted cohort start. For several possible index events, keep the existing cohort and require its earliest qualifying event to have a completed window. Numerator rules remain relative to the index event. Assess registration, survival, registers, age and exclusions at the reporting date. Apply the same rule in current and monthly macros so it also governs family unions and status models. Completed-window cohorts apply to IND80, IND88, IND104, IND113, IND121, IND161, IND196, IND197, IND198, IND199, IND200, IND202, IND223, IND234 and IND319. IND192 and IND272 already use completed windows. IND104 uses a rolling 12-month diagnosis cohort ending 35 days before the reporting date, with the start excluded and the end included.

For BMI measures, the earliest qualifying BMI controls the deadline. IND319 still requires the latest measured BMI to qualify; an invalid or out-of-range latest BMI prevents fallback. Its advice remains assessed against that latest BMI.

Use synthetic fixtures for temporal boundaries and aggregate-only warehouse checks. Development builds use the tracked `dev` target and existing `DEV__` layers. A worktree does not isolate warehouse objects.
